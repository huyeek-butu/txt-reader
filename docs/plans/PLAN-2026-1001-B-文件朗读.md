## 1. 目标

给阅读器加"念给我听"能力：从当前阅读位置开始按句朗读正文，朗读到哪高亮到哪，支持暂停/续读/语速调节，关闭页面后记住朗读位置。

## 2. 解决的问题

| 问题 | 说明 |
|---|---|
| 交互只有视觉通道 | 长时间盯屏易疲劳；通勤、做家务、闭眼休息时完全用不上 |
| 已有成果未复用 | 「按句分段」已算好句子边界，是 TTS 的天然基础，不用另写断句逻辑 |
| 自动翻页能力有限 | 自动翻页只是"到点翻页"，朗读是"读给你听"，长文本场景更实用 |

## 3. 实现要点

1. **引擎**：`window.speechSynthesis` + `SpeechSynthesisUtterance` —— 浏览器原生，零依赖、零成本、离线可用，符合"单文件零依赖"底线。
2. **断句来源**：直接复用 `Layout.splitSentences()`，按句喂给 TTS；句间按标点插入停顿（`。？！` 后稍长，`,` 后稍短）。
3. **同步高亮**：`utterance.onstart/onend` 驱动当前朗读句索引 → 复用现有 `visualRows` 渲染管线加类；**与搜索高亮做层叠，需明确优先级**。
4. **中文语音**：`speechSynthesis.getVoices()` 过滤 `zh-CN` / `zh-TW`，提供语音下拉；无中文语音时给**明确提示**而非静默失败。
5. **控制条**：接入现有 `.read-bar`（纯净阅读模式控制条）——▶ 朗读 / ⏸ 暂停 / ⏹ 停止 / 语速 0.5–2.0× / 音量；顶栏另放「🔊 朗读」入口供非纯净模式使用。
6. **位置记忆**：朗读位置并入现有 per-file 进度（`pendingProgress` + 内容指纹 key），下次打开接着念。

## 4. 覆盖场景

- 打开文件 → 从当前位置开始朗读，逐句高亮跟随
- 长文本连续朗读，跨页时自动跟随滚动/翻页
- 纯读模式下控制朗读；非纯读模式从顶栏进入
- 朗读中切换文件 / 改字号 / 切主题 → 正确停止并重置
- 关闭页面后重新打开 → 从上次朗读位置继续

## 5. 边界情况与已知坑（须实测确认）

| 情况 | 处理 |
|---|---|
| Chrome 对长 utterance 约 15 秒截断 | **按句切分正好规避**（每句通常远短于阈值）；仍需对超长句做二次切分 |
| 后台标签页/锁屏时 `speechSynthesis` 被节流暂停，`onend` 不触发 | 定时心跳检测兜底，判定卡死则重启当前句 |
| 系统无中文语音包（精简版 Windows） | 明确提示"请安装中文语音"，并禁用朗读按钮 |
| 朗读中用户手动滚动到别处 | 不中断朗读；高亮仍锚定朗读句（可提供"跟随朗读"开关） |
| 极短句（如"嗯。"）连续出现 | 避免高频重启 utterance 造成卡顿/吞字，可小批合并 |
| 空文件 / 未打开文件 | 按钮禁用，提示先打开文件 |

**交付说明（v1.1 追记）**

| 项 | 原规格 | 实际实现 | 理由 |
|---|---|---|---|
| 位置持久化存储 | 「并入现有 per-file 进度（`pendingProgress` + 内容指纹 key）」 | 复用**同一内容指纹 key**，但存于**独立 localStorage 键** `txtreader-speak-v1` | 现有进度记录的 `flushSave()` 直接整体覆盖 `map[key]`，若写入同一记录，翻页保存会抹掉朗读位置；独立键零风险且不触碰已验证的分页进度逻辑 |
| 改字号 / 切主题时的行为 | 「正确停止并重置」 | **不停止**，重排后按偏移重新定位高亮 | 队列项携带 (行号, 行内偏移)，偏移在重排后依然有效，故无需中断；停止反而打断听书体验。「正确重置」的实质要求（状态不残留、高亮不错位）已满足 |
| 高亮粒度 | 未明确 | **行级 class `#content .row.spk`**，非字符级 `<mark>` | 避免与搜索的 `<mark class="kw">` 在同一行内互相嵌套、切碎 HTML。中文句子通常 1–2 个视觉行内，行级高亮视觉上等同句级 |

其余实现细节（与规格一致）：`speechSynthesis` 引擎、`Layout.splitSentences` 断句、`MAX_CHUNK=60` 二次切分规避 Chrome 约 15 秒截断、看门狗（估时 = 字数×200ms/速率 + 6s 缓冲）自愈后台节流、无中文语音时明确提示并禁用、接入 `.read-bar` 控制条 + 顶栏入口。

**新增的规格外加固**（交付时一并做的健壮性处理）：

- **代际令牌 `gen`**：`synth.cancel()` 后旧 utterance 的 `onend`/`onerror` 仍会派发，若无条件推进索引会造成「跳句」。每次取消 `gen++`，回调只认自己那一代。
- **`onerror` 跳过不可念的块**：遇到非 `interrupted`/`canceled` 的错误只跳过该块，不卡死整条队列。
- **修复 PLAN-A 遗留缺陷**：`openFile()` 从未调用 `updateExportBtn()`，导致打开文件后「⤓ 导出结果」按钮始终禁用。已在本次一并修复并纳入回归断言。

**起点规则修订（v1.2 追记 · v1.14-speak-start）**

用户对朗读起点提出三条明确规则，覆盖 v1.0 规格中「从当前阅读位置开始」的最初设计：

| # | 规则 | 实现 |
|---|---|---|
| 一 | 正在朗读的行需有明确视觉标记，随朗读进度同步移动 | 行级 class `#content .row.spk` 承载四重标记：行首 `▶`（`.tx::before`，落在左内边距内，不推挤正文）+ 底部下划线（`inset` 阴影，不用 `border` 以免占掉 1px 行高导致末行被 `overflow` 截断）+ 左侧竖条 + 整行底色；随 `Speak.currentRange()` 逐句移动 |
| 二 | 首次触发朗读时，从**当前页面的第一行**开始 | `start()` 每次都调 `resolveStartIndex()`：`state.pages[currentPage()-1]` → 视觉行 → `lineIndex` → 队列中首个 `li >= 该行` 的块 |
| 三 | 停止后再次触发：有手动选定行 → 从该行起；否则仍从当前页第一行起 | 新增 `anchorLine`：点击正文任意一行选定（`.row.anchor`，accent2 竖条 + 行号变色），再次点击同一行取消；`setLines()` 重建逻辑行结构时自动失效 |

**影响与取舍**

- v1.1 记录的「朗读位置按文件持久化，重开页面可续读」**不再是起点来源**——规则二/三要求起点只能由「选定行 / 本页首行」决定。`savePos()` 的写入机制保留（记录「上次听到哪」），`restorePos()` 保留但不再影响 `start()` 的起点。
- **暂停 → 继续**（`playing && paused` 分支）不走起点重算，仍从原句续读；只有「停止后再次触发」才按规则重新定位。
- 扩展 API：`Speak` 新增导出 `getAnchor()` / `setAnchor(li)` / `resolveStartIndex()` / `pageFirstLine()`。
- 已知交互副作用：双击选词时的第一次 click 可能顺带选定该行（第二次 click 因存在选区而被过滤）。属可接受噪声，如需消除可改用「按下-抬起无位移」判定。

**验证**：`_test-speak-start.js` 45 项断言全通过（起点解析、选定行设置/取消/失效、暂停不重算起点、选定行越界回落、跨视觉行长行的页首归属、念完后再触发回页首、空队列安全）。

**可读性与停顿修订（v1.3 追记 · v1.15-speak-contrast-gap）**

用户反馈两条：①「浅色背景下，朗读的文字看不见」；②「缩短段落间的停顿时间」。

**① 朗读行不可见——根因（用像素证据定位，非推测）**

诊断链路：截图取像素 → 无头浏览器复现 → 计算样式核对。

| 证据 | 结论 |
|---|---|
| 用户截图朗读行文字实测 `#e8e3d6`（暗色主题文字色），底色 `#efe3cd`（羊皮纸阅读底色） | 对比度 **1.78:1**，低于可读阈值 → 看不见 |
| 同截图页面底色 `#efe3cd`、正文 `#564a31`，与阅读预设「羊皮纸」完全一致；而标记色实测等于 `#7fb3d3`（暗色主题的 accent） | 组合为**暗色应用主题 + 浅色阅读底色**，两者相互独立 |

三个缺陷叠加：

| # | 缺陷 | 修复 |
|---|---|---|
| 1 | `.spk .tx` 写死 `color: var(--text)`（应用主题文字色），ID 选择器权重高于阅读模式的 `body.reading-mode .tx` → 覆盖了 `--read-text` | **删掉该 color 声明**，文字色完全交由上下文决定 |
| 2 | `body.reading-mode .row { background: transparent !important }` 连朗读行的整行底色一起清掉 | 改为 `.row:not(.spk):not(.anchor)`，只清普通行；朗读/选定行另行恢复整行底色 |
| 3 | 标记色直接引用 `--accent`/`--accent2`（应用主题），与阅读底色无关 | 引入 `--spk-mark/--spk-fill/--anc-mark/--anc-fill`，默认取主题色（普通模式不变），阅读模式下由 `applyReadingSettings()` 按**阅读底色深浅**写入 `--read-*` 两档 |

配色档位（含对比度，5 种阅读预设全覆盖）：

| 阅读底色 | 朗读标记 | 选定标记 |
|---|---|---|
| 暖白 `#f6f1e7` | `#a25e08`（4.50:1） | `#1f6f8b`（5.04:1） |
| 米白 `#faf4e8` | `#a25e08`（4.63:1） | `#1f6f8b`（5.17:1） |
| 羊皮纸 `#efe3cd` | `#a25e08`（3.99:1） | `#1f6f8b`（4.46:1） |
| 墨紫 `#1c1a24` | `#f2b64d`（9.47:1） | `#8fb8e8`（8.33:1） |
| 石板 `#232733` | `#f2b64d`（8.21:1） | `#7fb8d8`（7.23:1） |

另：阅读模式下 `.tx` 左内边距为 `10vw`，原 `▶` 定在 `left: 2px` 会飘在窗口最左边、与正文脱节，改为 `left: calc(var(--read-pad-x) - 15px)` 贴到正文前。

**② 缩短段间停顿——机制**

原实现是「`onend` → 等 140ms → 再 `speak()`」，每次都要重付一次引擎启动延迟，句与句之间因此出现可感知空档。改为**预排队（lookahead）**：当前块 `onstart` 时就把下一块 `speak()` 进引擎队列，由引擎自己无缝接续。

| 项 | 改前 | 改后 |
|---|---|---|
| 句间衔接 | 等 `onend` 后起 140ms 定时器再发 | 预排队，**无等时器间隔** |
| `GAP_MS` | 140ms（常规路径） | 60ms（**仅兜底**：预排队失效时） |
| 高亮推进时机 | `speak()` 时（早于发声） | `onstart` 时（与发声同步，更准） |
| 预排队深度 | — | 1 块（不占内存、不引发取消风暴） |

**引入预排队后必须补的两个防护**（否则会从「停顿长」变成「停住」）：

1. **取消一致性**：`synth.cancel()` 后旧 `onend` 仍会派发。新增 `cancelAll()` 统一做 `gen++ / nextPre=null / cancel / clearTimers`，四条取消路径（stop / jumpTo / setRate / setLines）+ 看门狗超时全部改走它。`onend`/`onerror` 增加 `i !== idx` 判定，忽略迟到回调。
2. **交接保护**：预排队让「等 `onend` 起定时器」这条兜底失效——若引擎把预排的块悄悄丢了，`onend` 已清掉看门狗，整条队列会静默停住。新增 `armTransitionGuard()`：交接窗口挂 2.5s 短看门狗，下一块迟迟不开声就重发它。

**未纳入（用户未提，不擅自扩）**：停顿时间的用户可调项（如「紧凑/标准/舒缓」档）。当前为固定值，如需要可再加。
