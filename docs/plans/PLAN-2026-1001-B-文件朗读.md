## 1. 目标

给阅读器加"念给我听"能力：从当前阅读位置开始按句朗读正文，朗读到哪高亮到哪，支持暂停/续读/语速调节，关闭页面后记住朗读位置。

## 2. 解决的问题

| 问题 | 说明 |
|---|---|
| 交互只有视觉通道 | 长时间盯屏易疲劳；通勤、做家务、闭眼休息时完全用不上 |
| 已有成果未复用 | 「按句分段」已算好句子边界，是 TTS 的天然基础，不用另写断句逻辑 |
| 自动翻页能力有限 | 自动翻页只是"到点翻页"，朗读是"读给你听"，长文本场景更实用 |

## 3. 实现要点

1. **引擎**：`window.speechSynthesis` + `SpeechSynthesisUtterance` —— 浏览器原生，零依赖、零成本、离线可用，符合"单文件零依赖"底线。
2. **断句来源**：直接复用 `Layout.splitSentences()`，按句喂给 TTS；句间按标点插入停顿（`。？！` 后稍长，`,` 后稍短）。
3. **同步高亮**：`utterance.onstart/onend` 驱动当前朗读句索引 → 复用现有 `visualRows` 渲染管线加类；**与搜索高亮做层叠，需明确优先级**。
4. **中文语音**：`speechSynthesis.getVoices()` 过滤 `zh-CN` / `zh-TW`，提供语音下拉；无中文语音时给**明确提示**而非静默失败。
5. **控制条**：接入现有 `.read-bar`（纯净阅读模式控制条）——▶ 朗读 / ⏸ 暂停 / ⏹ 停止 / 语速 0.5–2.0× / 音量；顶栏另放「🔊 朗读」入口供非纯净模式使用。
6. **位置记忆**：朗读位置并入现有 per-file 进度（`pendingProgress` + 内容指纹 key），下次打开接着念。

## 4. 覆盖场景

- 打开文件 → 从当前位置开始朗读，逐句高亮跟随
- 长文本连续朗读，跨页时自动跟随滚动/翻页
- 纯读模式下控制朗读；非纯读模式从顶栏进入
- 朗读中切换文件 / 改字号 / 切主题 → 正确停止并重置
- 关闭页面后重新打开 → 从上次朗读位置继续

## 5. 边界情况与已知坑（须实测确认）

| 情况 | 处理 |
|---|---|
| Chrome 对长 utterance 约 15 秒截断 | **按句切分正好规避**（每句通常远短于阈值）；仍需对超长句做二次切分 |
| 后台标签页/锁屏时 `speechSynthesis` 被节流暂停，`onend` 不触发 | 定时心跳检测兜底，判定卡死则重启当前句 |
| 系统无中文语音包（精简版 Windows） | 明确提示"请安装中文语音"，并禁用朗读按钮 |
| 朗读中用户手动滚动到别处 | 不中断朗读；高亮仍锚定朗读句（可提供"跟随朗读"开关） |
| 极短句（如"嗯。"）连续出现 | 避免高频重启 utterance 造成卡顿/吞字，可小批合并 |
| 空文件 / 未打开文件 | 按钮禁用，提示先打开文件 |

- [ ] 朗读位置持久化，重开页面可续读
