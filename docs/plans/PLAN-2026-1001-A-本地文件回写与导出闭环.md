## 1. 目标

让阅读器从"只读"变为"可加工"：排版结果能真正落盘，而不只是复制粘贴到剪贴板。

## 2. 解决的问题

| 问题 | 现状证据 |
|---|---|
| 排版产物无法保存 | 「✒ 简单排版」弹窗输出与主窗口「正文排版」视图**均只能复制**，保存需手动开编辑器粘贴 |
| 单一 API 依赖风险 | v1.8.1 教训：仅依赖 File System Access API，在预览沙箱环境不可用导致功能失效并被回退 → 必须双路降级 |

## 3. 实现要点

1. **主路（能力优先）**：`showSaveFilePicker`（FSA 可用时）→ 回写原文件 / 另存新文件；持有 file handle，支持再次保存。
2. **备份路（保底）**：`Blob` + `a[download]` 下载；默认文件名加 `.layout.txt` 后缀，避免误覆盖原文件。
3. **入口**：
   - 「✒ 简单排版」弹窗 → 新增「保存为 TXT」按钮
   - 主窗口 → 新增「导出当前排版结果」按钮
4. **安全约束**：回写原文件属不可逆操作（L2）——**必须先确认**，默认走另存；确认信息含：写哪个文件 · 后果 · 能否撤回 · 编号选项。
5. **编码一致**：读写使用同一 `state.enc`，避免回写后乱码。
6. **环境探测**：启动时检测 `typeof window.showSaveFilePicker === 'function'`，仅启用对应主路，避免出现按钮点了没反应的死路。

## 4. 覆盖场景

- 打开本地 TXT → 主窗口排版 → 导出为新文件
- 弹窗粘贴文本 → 排版 → 保存为下载文件
- FSA 可用环境下 → 覆盖保存回原文件（需确认）
- FSA 不可用环境 → 自动降级为下载

## 5. 边界情况

| 情况 | 期望行为 |
|---|---|
| FSA 不可用（Firefox/Safari/预览沙箱） | 静默降级为下载，不报错、不显示失效按钮 |
| 用户取消保存对话框 | 捕获 `AbortError` 静默处理，不提示错误 |
| 未打开文件时点导出 | 按钮禁用或提示"请先打开文件" |
| 空排版结果 | 不落盘，提示"无内容可保存" |
| 超大文件导出 | 复用原有 Blob 路径；注意内存峰值（与 `PLAN-C` 联动观测） |

## 6. 验收判据

- [ ] FSA 可用环境：排版结果可覆盖保存回原 TXT，重新打开内容正确、无乱码
- [ ] FSA 不可用环境：点击导出可下载到文件，内容与预览一致
- [ ] 取消对话框不产生任何报错提示
- [ ] 覆盖保存前出现明确确认，用户可取消
- [ ] 读写编码一致（GBK / Big5 / UTF-8 各测一次）
- [ ] 单文件零依赖约束不被破坏（不引入外部库）
